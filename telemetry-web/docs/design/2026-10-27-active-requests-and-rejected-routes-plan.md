**Goal:** `nethttp.Handler` reports how many requests are in progress, and
the chi adapter's `RouteTag` names the route of a request that middleware
answered before chi routed it.

**Architecture:** A small wrapper around the otelhttp handler keeps the
OpenTelemetry `http.server.active_requests` up-down counter; it is built
inside the existing `followMeter`, so it follows the global meter provider
like the rest. In the chi adapter, `RouteTag` falls back to chi's
`Routes.Find` (which follows mounted sub-routers and returns the joined
pattern) when `RoutePattern()` is empty.

**Tech Stack:** Go 1.25 modules
`github.com/stakater/operator-utils/telemetry-web` and
`.../telemetry-web/adapters/chi` (chi v5.2.1), OpenTelemetry Go v1.44.0
(semconv `v1.41.0/httpconv`), otelhttp v0.69.0, standard `testing`.

**Spec:** the gateway repository (`stakater-ab/cloud-orchestrator-gateway`),
branch `feat/sco-gateway-metrics`,
`docs/superpowers/specs/2026-10-27-gateway-operational-metrics-design.md`,

## Findings that refine the spec

- otelhttp v0.69.0 does not emit `http.server.active_requests`
  (`internal/semconv/server.go` builds only duration and body-size
  instruments), so it is new code. `docs/reference.md` already lists it as
  coming from otelhttp; that line is wrong today and is corrected here.
- The OpenTelemetry convention requires two attributes on it:
  `http.request.method` and `url.scheme`. The spec said "method only";
  `url.scheme` adds at most two values (`http`, `https`).
- chi v5.2.1's `Routes.Find(rctx, method, path) string` returns the full
  joined pattern, sub-routers included; `Match` only answers yes or no.
  `Find` is used.
- The lookup needs the router chi records in the routing context
  (`rctx.Routes`). chi only sets it when the `Mux` creates the context
  itself. A dispatcher that hands a router a context made with
  `chi.NewRouteContext()` (the gateway's `organizationHandler` does) must
  set `Routes` on it, or no lookup happens. The gateway plan covers that.

// activeCount sums http.server.active_requests for one method.
func activeCount(t *testing.T, method string) int64 {
	t.Helper()
	var rm metricdata.ResourceMetrics
	if err := reader.Collect(context.Background(), &rm); err != nil {
		t.Fatalf("collect: %v", err)
	}
	var total int64
	for _, sm := range rm.ScopeMetrics {
		for _, m := range sm.Metrics {
			sum, ok := m.Data.(metricdata.Sum[int64])
			if m.Name != "http.server.active_requests" || !ok {
				continue
			}
			for _, dp := range sum.DataPoints {
				v, ok := dp.Attributes.Value(attribute.Key("http.request.method"))
				if ok && v.AsString() == method {
					total += dp.Value
				}
			}
		}
	}
	return total
}

// serveIgnoringPanic serves one GET and swallows a panic that escapes h, as
// net/http's server does.
func serveIgnoringPanic(h http.Handler, path string) {
	defer func() { _ = recover() }()
	get(h, path)
}

// The count goes up for the length of a request and back down afterwards,
// also when the handler panics, and never for a skipped path.
func TestActiveRequests(t *testing.T) {
	tests := []struct {
		name       string
		opts       []Option
		panics     bool
		wantInside int64
	}{
		{name: "counted while served", wantInside: 1},
		{name: "panic recovered", panics: true, wantInside: 1},
		{name: "panic escaping", opts: []Option{WithoutRecovery()}, panics: true, wantInside: 1},
		{name: "skipped path", opts: []Option{WithSkipPaths("/active")}},
	}
	for _, tt := range tests {
		t.Run(tt.name, func(t *testing.T) {
			before := activeCount(t, http.MethodGet)
			var inside int64
			h := Handler(http.HandlerFunc(func(http.ResponseWriter, *http.Request) {
				inside = activeCount(t, http.MethodGet) - before
				if tt.panics {
					panic("kaboom")
				}
			}), tt.opts...)
			serveIgnoringPanic(h, "/active")
			if inside != tt.wantInside {
				t.Errorf("during the request: delta = %d, want %d", inside, tt.wantInside)
			}
			if after := activeCount(t, http.MethodGet) - before; after != 0 {
				t.Errorf("after the request: delta = %d, want 0", after)
			}
		})
	}
}

// countActive keeps http.server.active_requests: up when a request starts,
// down when it ends. otelhttp v0.69 does not emit it. It sits outside
// otelhttp so a panic escaping under WithoutRecovery still brings the count
// down, and it is built per provider like the handler it wraps.
func countActive(next http.Handler, mp metric.MeterProvider) http.Handler {
	meter := mp.Meter(ident.ModulePath, metric.WithInstrumentationVersion(ident.Version()))
	// On error this is a working no-op; the only cause is an invalid name,
	// which the constant name rules out.
	active, _ := httpconv.NewServerActiveRequests(meter)
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		if skipped(r.Context()) {
			next.ServeHTTP(w, r)
			return
		}
		method, scheme := activeAttrs(r)
		active.Add(r.Context(), 1, method, scheme)
		defer active.Add(r.Context(), -1, method, scheme)
		next.ServeHTTP(w, r)
	})
}

// activeAttrs returns the attributes the convention requires on
// http.server.active_requests, normalized as otelhttp normalizes them on its
// duration metric so the two line up: unknown methods become _OTHER.
func activeAttrs(r *http.Request) (httpconv.RequestMethodAttr, string) {
	method := httpconv.RequestMethodOther
	if m := strings.ToUpper(r.Method); stdMethods[m] {
		method = httpconv.RequestMethodAttr(m)
	}
	if r.TLS != nil {
		return method, "https"
	}
	return method, "http"
}

// DurationStatusCountNoRoute returns the cumulative
// http.server.request.duration observation count with the given status and
// no http.route at all: the requests no route was stamped on.
func DurationStatusCountNoRoute(rm metricdata.ResourceMetrics, status int) uint64 {
	var total uint64
	eachHist(rm, "http.server.request.duration", func(dp metricdata.HistogramDataPoint[float64]) {
		_, routed := dp.Attributes.Value(attribute.Key("http.route"))
		c, ok := dp.Attributes.Value(attribute.Key("http.response.status_code"))
		if !routed && ok && c.AsInt64() == int64(status) {
			total += dp.Count
		}
	})
	return total
}

// rejectAll answers 401 before chi routes, as authentication middleware does.
func rejectAll(http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, _ *http.Request) {
		w.WriteHeader(http.StatusUnauthorized)
	})
}

func okFunc(w http.ResponseWriter, _ *http.Request) { w.WriteHeader(http.StatusOK) }

// route at all when wantRoute is "".
func assertRejected(t *testing.T, h http.Handler, path, wantRoute string) {
	t.Helper()
	count := func() uint64 {
		rm := adaptertest.Collect(t)

		}

```go
// RouteTag stamps http.route (the matched route pattern) on the server span and
// the duration metric, and renames the span to "{method} {route}". chi fills in
// RoutePattern during routing, before the handler runs, so the stamp is
// deferred and survives a panic unwinding past it.
//
// Middleware that answers before chi routes (authentication returning 401,
// say) leaves RoutePattern empty. RouteTag then stamps the pattern chi would
// have matched, so the rejection is attributed to its route. A request that
// matches no route gets none. The lookup needs the router in the routing
// context (chi sets it; a context made with chi.NewRouteContext needs Routes
// set by hand) and is skipped when RouteTag sits inside a mounted router,
// which keeps the mount's pattern.
func RouteTag() Middleware {
	return func(next http.Handler) http.Handler {
		return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
			rctx := chi.RouteContext(r.Context())
			// Captured now: routing into a mounted router sets RoutePath.
			topLevel := rctx != nil && rctx.RoutePath == ""
			defer func() {
				if route := matchedRoute(r, topLevel); route != "" {
					nethttp.StampRoute(r.Context(), r.Method, route)
				}
			}()
			next.ServeHTTP(w, r)
		})
	}
}
```

```go
// matchedRoute returns the pattern chi routed on or, when nothing was routed
// and RouteTag runs on the top-level router, the pattern it would have used.
func matchedRoute(r *http.Request, topLevel bool) string {
	if route := routePattern(r); route != "" || !topLevel {
		return route
	}
	return wouldMatch(r)
}

// wouldMatch asks the router in the routing context which pattern r would
// match, with the path chi's own routing uses. Find follows mounted routers
// and returns the joined pattern, or "" when nothing matches.
func wouldMatch(r *http.Request) string {
	rctx := chi.RouteContext(r.Context())
	if rctx == nil || rctx.Routes == nil {
		return ""
	}
	path := r.URL.RawPath
	if path == "" {
		path = r.URL.Path
	}
	return rctx.Routes.Find(chi.NewRouteContext(), r.Method, path)
}
```

```markdown
Two additions for web services using telemetry-web, found missing while
adding operational metrics to the SCO gateway.

## Requests in progress

`nethttp.Handler` now reports `http.server.active_requests`, the
OpenTelemetry up-down counter of requests being served, labelled by method
and scheme as the convention requires. otelhttp does not emit it, although
`docs/reference.md` said it did. It shows load at a glance, including
long-lived requests such as WebSocket sessions. Skipped paths are left out,
like the other `http.server.*` metrics.

## Routes for requests rejected before routing

In chi, middleware such as authentication runs before the router matches,
so a `401` carried no `http.route` and could not be told apart by route. The
chi adapter's `RouteTag` now records the route the request would have
matched. A path that matches no route still gets none, so the number of
series stays bounded by the routes defined.

A dispatcher that serves a chi router under a routing context it made with
`chi.NewRouteContext()` must set `Routes` on that context for the lookup to
work; this is documented in `docs/reference.md`.

## Left out

- The same lookup for gin and echo: not needed yet.
- Adapter pins and tags: they follow `docs/releasing.md` after merge.
```
